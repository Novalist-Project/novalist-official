## Evidence boundary and immediate blockers

The existing rich editor has one `#editor` contenteditable and one `NovalistEditorState.editor`, `lastHtml`, composition state, annotation collection, proofing state and pending action state (`public/editor/editor-state.js`, `content-input.js`). `setSceneContext` changes one scene identity; `setContent` replaces the whole editor's children, clears dictation/composition/proofing/readability and can reset scrolling. `getContent`, `getPlainText` and pending capture serialize/read the entire root. `editorContentMessages.ts` attributes a content message to the current pane without a scene/revision in the message. A wrapper that merely puts several scene nodes under that root does not supply per-scene ownership.

`useEditorAnnotations.ts` stores one scene's comments/footnotes and persists through current `paneIds()`. `editorActionMessages.ts` chooses split and inline-action context from the pane; extension context-menu execution uses global `openChapterGuid/openSceneId`. `useEditorSynchronization.ts` binds scene changes to whole-root `setContent`, and compares one HTML baseline. These paths require scene-addressed adaptation before reuse.

Native `execCommand` formatting/lists, `Range.extractContents` highlight/comment operations, normal cut/delete/paste/drop and suggested deletion can consume/move nested scene wrappers. There is no demonstrated protected common-root boundary policy. Pagination treats direct root children as blocks; if each child becomes an entire scene, it can paginate whole scenes as indivisible units. `proseBlocks`/`blockOf`, offsets and selection restoration must understand scene containers and structural chrome.

`footnote-navigation.js:38-72` implements `splitAtCaret` by cloning from the entire editor root to the selection's start and from there to the entire root's end. It does not require a collapsed selection, and explicitly rejects empty beginning/end halves. The common-root implementation must split only the source scene, reject noncollapsed structural commands, and allow edge halves as the new specification requires. Existing behavior cannot be reused unchanged.

Existing `editor-*.spec.ts` exercises the single-scene editor. `collaboration-manuscript.spec.ts:93-94` explicitly asserts three legacy `.scene-editor` roots and retention of one root; it does not prove selection/editing across a shared editable root. Backend multi-scene tests prove service behavior, not DOM selection, retained history or coordinated common-root saves. Experimental work by another agent is intentionally outside this baseline inventory.
